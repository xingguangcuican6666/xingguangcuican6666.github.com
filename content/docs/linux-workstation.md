# Linux workstation and workflow

> Public note derived from the profile line `Arch Linux + Hyprland`.

## Why mention the workstation at all

很多个人站会把开发环境写成一句装饰性标签。
这里更有价值的做法，是把它解释成工作方式的一部分。

公开资料里提到日常环境是 `Arch Linux + Hyprland`。
这至少说明了几件事：

- 工作环境偏向可定制和可控
- 不排斥直接面对系统层细节
- 工具选择会服务于效率，而不是服务于“默认配置”

这与整个站点里低层 Android、安全研究、自动化脚本这些主题是连得上的。

## What this environment supports well

对这类仓库和工作流来说，Linux 桌面环境通常擅长这些事情：

- 快速切换多个终端和调试上下文
- 直接使用 shell 脚本串联任务
- 更容易接入 ADB、交叉编译、打包和设备侧实验
- 把“工具链问题”留在自己可控的环境里解决

`Hyprland` 在这里不是为了展示炫酷桌面，而更像一个信号：
日常环境强调效率、布局自由和对窗口工作流的掌控。

## The engineering posture behind it

站点里不需要放详细 dotfiles，但可以隐含一种工程姿态：

- 配置是为了工作，不是为了截图
- 自动化优先于重复手工步骤
- 能拆成脚本的过程，就不应该长期靠记忆维护

这和公开技术栈里出现的 `Shell`、`Batch`、`Kotlin`、`C/C++` 是相互印证的。

## What belongs in public notes

适合写在这里的是：

- 环境选择与技术方向之间的关系
- 为什么这种桌面/工具链组合适合当前工作
- 它如何支撑 Android 与系统底层实验

不适合写在这里的是：

- 全量配置文件
- 高频变化的快捷键细节
- 与当前站点主题没有直接关系的桌面美化内容

## Short version

如果要把这条信息压缩成一句话，可以这样理解：

`Arch Linux + Hyprland` 不是个人口味展示，而是一个和低层 Android、安全研究、脚本化工作流相匹配的开发环境选择。
